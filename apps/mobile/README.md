# Voics mobile (Expo, React Native)

iOS first, Android from the same code ([client#203](https://github.com/discordy-voics/client/issues/203), plan: docs `plans/2026-11-03-mobile-app.md`, stack: ADR 0024). The app signs in (with two-factor), keeps a gateway connection that resumes when the app returns to the foreground, and lists your servers and their channels of every kind the desktop sidebar shows (text, announcement, voice, stage, forum). Tapping a text channel opens its messages (read, send, reply, edit, delete, reactions). There is no tab bar: the main screen follows the desktop client, a narrow server rail on the left (Direct messages on top, a separator, then servers and folders with the same selected pill, unread pip and mention badge) beside a column with the selected server's name and channels by category (or the DM list), and a user panel at its foot. Tapping a channel or conversation opens the chat full screen over the rail; the back arrow, the iOS edge swipe and the Android back button return to it. The bell in the column header opens Notifications and the user panel (name or gear) opens Settings. The DM column lists your 1:1 and group conversations (newest first) and opens them in the same message screen; encrypted conversations show the private-delivery notice. The chat header follows desktop: back chevron only (no route name) on every pushed screen, then `# channel` in a server, or the friend's avatar and name in a 1:1 DM with voice call, video call (both show a "not in this test version" notice) and profile buttons; the server members button sits in the right-hand slot (see Servers below). Messages show avatars, role-coloured names and times with consecutive messages grouped, markdown text, system messages (join, pin, call, group changes), the edited marker and the message being replied to above the reply; long-pressing a message opens a bottom sheet with react, reply, Copy Text, Select Text (a sheet with natively selectable text), edit and delete. The composer is a tall rounded field that grows with the text, with a + button (photo library, camera, files; previews with remove, 25 MB and 10 files per message) whose buttons centre on a single-line input, and an emoji button that opens the picker and inserts at the cursor. Long-pressing a message also offers Copy Message Link, Mark Unread and (with Manage Messages) Pin; the + chip under a message and More reactions open the same picker, and long-pressing a reaction lists who reacted. Dragging a message left 64 pt replies with a haptic tick. The header's ... button opens a menu with Mark as read, Mute (durations) or Unmute, Notification settings (server default, all, mentions, nothing) and Invite people, a send button that appears with text, and a `Message #general` / `Message @bob` hint; it rides the keyboard frame by frame (see Motion and design below). Opening a chat acks the latest message so its unread dot clears, like desktop. Tapping an author, or the profile button in a 1:1 DM, opens their profile (avatar, names, About me, Friends since). Attachments show as an image and video grid (up to four tiles, then +N, spoilers blurred until tapped) with a full-screen viewer (swipe, pinch to zoom), audio and file rows, and unsent messages show upload progress with Cancel; they upload through the core presigned-slot flow with an XMLHttpRequest progress adapter (`src/adapters/xhrUpload.ts`). Opening a chat shows a New divider above the first unread message and a count bar with Mark as read, scrolls to it, and a Jump to latest button appears after scrolling away. It has not been run on a device or simulator yet; the tests use Jest with mocks.

**Servers (client#274).** Voice and stage channels sit in their categories with the speaker icon, the user limit and the people connected right now (avatar, name, muted, deafened, camera and live marks, from voice state). Tapping one opens a screen with the channel and its people. In Expo Go it says "Voice isn't in this test version yet"; in a development build it has a Join voice button (see Voice and calls below). Ephemeral and peer-to-peer channels show the lock (or link) icon and open on a plain message; forum channels open on their posts (see Forums below). The people icon in a server channel's header opens the member list (slides in from the right; grouped by hoisted role, then online and offline; avatars with status dot, role colour, owner crown, activity line, search, collapsible groups); tapping a person opens their profile sheet (roles, member since, About me) with a Message button that opens the DM. Tapping the server name opens the server menu: Invite people (expiry and use limit, then copy or share the link), Server settings (only with Manage Server, Manage Roles or Manage Channels) and Leave server (after a confirmation; not for the owner). Server settings has Overview (name, icon from the photo library), Roles (list with member counts and hierarchy locks; per role name, colour, display options and every permission, with the same locks the desktop applies), Members (search; kick and ban only for people you outrank, after a confirmation), Invites (create, copy, revoke) and Channels (create channel or category, rename, delete after a confirmation). Every page checks the same permissions as desktop and shows a note instead of controls when a deep link or a role change leaves the user without access. Not built from desktop's server settings: Emoji, Template, Discovery, Bans (the list and unban), Audit log, server banner and invite splash, description, voice region, system messages, inactive channel, default notifications, prune members, role reordering, duplicating a role, role icons, adding roles to members and members-with-a-role, per-member timeout, nickname, mod view, channel permission overwrites, topic, slowmode, age restriction and reordering of channels, pinned channels, the right-edge swipe that would open the member list, and Delete server. Attachments are next (client#206 follow-ups). It has not been run on a device or simulator yet; the tests use Jest with mocks.

**Notifications and direct messages (client#278, wave 2).** The bell opens the mentions inbox (`src/notifications`): the same entries as desktop's Mentions (core `mentionInboxStore`, filled by the dispatch router), grouped by server, newest first; tapping one calls `openMessage`, which asks the chat for a jump (`useReadNavStore.requestJump`) and pushes the chat route. The chat serves the jump in `useJumpToMessage`: it scrolls to the message when it is loaded, otherwise `MessageService.loadAround` fetches the window around it, the list then holds a window detached from the present (`hasMoreAfter`), `onStartReached` extends it with `loadNewer`, nothing is acknowledged while detached, and Jump to latest reloads the newest page. Reply previews, and later pins and search hits, use the same path. Mark read removes the entry (it does not ack the channel); Mark all read clears the list. `InAppBanner` (mounted in the root layout) shows a banner for `offerBanner(message)`, which the runtime calls for every incoming message; core's `incomingAlert` decides (own and silent messages, the chat on screen from the route (`channelIdFromPath`), mute, level, @everyone and role settings, Do Not Disturb) and the app must be in the foreground. The DM column adds Friends and New message rows, pinned conversations (`pinned_dm_channel_ids`, at most five, synced through user settings) and a long-press menu built from core's `buildDmMenu` (`src/dms/DmMenu.tsx`). `dms/new` is the New message picker (core `dmCandidates`; one person opens the DM, several create a group DM) and `friends` is the Friends page (core `friendsModel`: Online, All, Pending, Blocked, Add friend with `friendRequestError`). Group settings (name, icon, members) are not on mobile yet. It has not been run on a device or simulator yet; the tests use Jest with mocks.

**Find and navigate (client#278, wave 2).** Tapping the chat title opens `ChannelDetails` (a bottom sheet: name, topic, Search, Pinned messages, Threads in a server text channel, Members, Copy link; a 1:1 DM opens the profile instead, a group lists its people). `pins/[channelId]` is the Pins panel (`api.pins`, reloaded when `last_pin_timestamp` changes; Jump sets a jump request and goes back to the chat, Unpin needs Manage Messages in a server); the pin notice's link and details open it. `ProfileSheet` is the full profile: banner from `accent_color`, status dot and activity, `profileActions` (Message, Add friend, Accept, Remove friend, Request sent, Block with confirmation, Unblock), the note (core `saveUserNote`, saved on blur, restored on failure) and, from `userProfile`, mutual servers and friends; a sheet with a field lifts with the keyboard frame (`useReanimatedKeyboardAnimation`). Threads: core `threads` (naming, lookup, listing, locked rule); Create Thread in the message menu needs Create Public Threads in a channel that is not a thread (`NewThreadSheet` then `api.createThread`); a thread is a guild channel of type 10 to 12, opened through the same chat route with the parent channel's overwrites and Send Messages in Threads; `threads/[channelId]` lists the threads the client has (GUILD_CREATE and THREAD_CREATE), because the server has no list route yet (api#34). Search (`search/[channelId]`): core `SearchService.page` with `searchCandidates`, the query language and suggestions of `messageSearch`; Media runs `has:image` and `has:video` and merges, Files and Links run `has:file` and `has:link` (the Files tab drops images and videos, Links extracts the URLs from the text), results load a page at a time; chats with private delivery cannot be searched on mobile. Join a server: the + at the end of the rail opens `JoinServerSheet` (core `parseInviteCode`, `api.invite` for the preview, `api.acceptInvite`; a server you are in just opens). Voice channels have Open text chat, which opens the chat route with `chat=1`. Forum posts, group settings and rail reordering came in wave 3; report has no api yet.

**Settings and account (client#279, wave 3).** The user panel opens `settings` (`src/settings`): a search field over every page and row (core `settingsSearch`, the ranking desktop's settings search uses too; a result opens the page with the row marked) and the pages grouped as on desktop, then Log out (asks first, with desktop's wording). Pages: My account (username, email and password changes, two-factor setup, removal and backup codes, disable and delete, all behind the same password and typed-username steps as desktop; the email-verification banner; the authenticator key is shown to type in and an Open authenticator app button follows the `otpauth` link, because there is no QR drawing library in Expo Go), Profile (avatar and banner from the photo library, display name, About me, colour, status and custom status with expiry; sends only changed fields), Privacy and delivery (the default mode, with the encrypted modes switched off and explained because the encryption core is not in the app yet, per-chat overrides with Clear, and Blocked users with Unblock), Devices and sessions (core `authSessions`, Log out per device and for all others after a confirmation, the encrypted-message devices), Appearance, Accessibility, Notifications and Chat. Only settings the phone app honours are listed: desktop's Voice and video, Keybinds, Connection, Desktop, Advanced, Developer and About are desktop-only, and desktop has no Language page. Theme (Dark, OLED, Light), accent and Match iPhone appearance use `appearance/palettes.ts` (desktop's tokens converted to sRGB): styles read `theme` once when their module loads, so `appearance/boot.ts` (imported by the root layout right after `install`) rewrites the shared `theme` object from the stored preferences, and a new choice shows from the next start of the app (the page says so). Text size scales message text; reduce motion (also from the iPhone), role colours (in the name, as a dot, hidden), always-underline links, Display images and videos, spoiler display, reactions and emoticon conversion take effect at once. `PrefsSync` runs on mobile as on desktop, so theme, accent, text size, reduce motion, role colours, link underline and only-mentions follow the account. Report and block: Block User is in the message menu (not for yourself, bots or people already blocked) next to the profile sheet and the Friends tab, always after a confirmation; there is no report endpoint in the api (the moderation spec lists `POST /channels/{id}/messages/{id}/report` as not built), so the app has no Report control rather than one that cannot work. Not built in this wave: QR login (gateway#17). It has not been run on a device or simulator yet; the tests use Jest with mocks.

**Server administration (client#279, wave 3).** Server settings now has Emoji (upload from the photo library with the 256 KB bound, rename, delete after a question; Manage Expressions), Bans (list with reasons, search over name, id and reason through core `filterBans`, Unban after a question; Ban Members) and Audit log (core `AUDIT_ACTIONS` and `AUDIT_FILTERS`, filter by action and moderator, Load older entries with `before`; View Audit Log), each gated by `settingsPages` like desktop's tabs. Like desktop, the server menu only offers Server settings with Manage Server, Manage Roles or Manage Channels, so a member who holds only Ban Members, View Audit Log or Manage Expressions cannot reach those pages from the menu. The Members page opens `MemberActionSheet` for a member (also from the Manage member button of the profile sheet in a server): Roles (switches for roles below your highest, `assignableRoles`), Change nickname or Edit server profile for yourself (Manage Nicknames or Change Nickname), Timeout with desktop's presets and Remove timeout, Kick and Ban with the message-history window and a reason; every entry comes from core `memberCapabilities` (same hierarchy rules as desktop) and the page has a Timed out only filter. Roles has a Reorder mode with up and down buttons built on core `reorderPositions` (roles at or above yours never move) and `reorderRoles`. Channels has Reorder (core `channelOrder` step functions, one bulk `reorderChannels`, reverted when refused, with desktop's offer to sync permissions after moving into another category) and a page per channel: name, topic, slowmode, age restriction, voice user limit and bitrate, Delete channel after a question, and Permissions with allow, inherit or deny per permission for roles and members (`putOverwrite` and `deleteOverwrite` for what changed). The server menu adds Mark as read, Mute server (durations) or Unmute, Notification settings (level, suppress @everyone and role mentions, hide muted channels, via core `notificationActions`) and, for the owner, Delete server, which asks for the server name to be typed first (desktop asks a plain question). Marking read, saving the rail, leaving and deleting a server, and sending channel moves moved into core (`guildCommands`, `channelOrderCommands`) and desktop uses them. Not built: Template and Discovery pages, server banner and splash, description, voice region, system messages, inactive channel, default notifications, prune, duplicating roles, role icons, members-with-a-role, Mod View, drag handles (reordering uses buttons).

**Servers, discovery and groups (client#279, wave 3).** The + at the end of the rail opens Add a server: Create my own server (`CreateServerSheet`: empty or a built-in template from `builtinGuildTemplates`, or a pasted template link previewed with `guildTemplate`, then a name of at least two characters; the new server opens), Join a server (as before) and Discover servers (`discover`: public servers that opted in, searched after a short pause, narrowed by category or tag, Load more, Join or Open; the same `discoveryGuilds` calls as desktop). Long-pressing a server or folder in the rail opens `RailMenu` instead of dragging: Move up and down (inside a folder, or among the entries), Add to folder, Make a folder with another server, Remove from folder, and for a folder Rename or colour, Move and Ungroup, built on core `railLayout` through `railEditModel` and saved with core `saveRail` (shown at once, reverted if the save fails). Group DMs have a Group settings row in the chat details (`groups/[channelId]`): name, icon from the photo library, members (any member adds friends, only the owner removes people after a question, 25 at most) and Leave group; in an encrypted group the member controls are hidden with a note because changing who is in it needs a membership commit from the encryption core, which the mobile app does not have. A message with an invite link to this instance shows an invite card (server, who is in it, Join or Joined; lookups cached per code, dead links shown as invalid), and tapping such a link, or a `voics://invite/` link, opens the join sheet in the app (`InviteLinkSheet` in the root layout) instead of the browser. The deep link from outside the app needs the native build. Search has a Sort row (Newest, Oldest, Most relevant; core `SEARCH_SORTS`), which searches again from the start. Not built from this part of the plan: drag handles for reordering, server banner and splash.

**Forums, forwarding, drafts and the offline cache (client#279, wave 3).** A forum channel with server-stored delivery opens `ForumScreen`: its posts (public threads under it, active first and newest first, with their message counts), and New post (a title and a first message, sent as `createThread` with a `message`, as desktop sends it) only for someone who passes the same Create Public Threads check as starting a thread; opening a post shows it as a chat. Forward is in the message menu for messages stored on the server (not system messages, unsent ones or messages of private chats); `ForwardSheet` lists recent DMs and groups, then channels you may send in (core `forwardTargets` and `permissionsInChannel`), with an optional comment, and sends through core `forwardMessage`; private chats and encrypted server channels are shown disabled so nothing encrypted is ever forwarded in the clear. A forwarded message shows a Forwarded block with the copied text and files. Drafts: the composer keeps unsent text per chat in core `useDraftStore` after a short pause and when you leave the chat, restores it when the chat opens and clears it on send; chats with private delivery keep nothing. The offline cache (`src/offline/messageCache.ts`, in the installed device key-value store) saves the newest 50 sent messages of up to 30 server-stored chats when a chat loads and when it is left; opening a chat shows the saved messages at once and replaces them with the fresh page, and when the server cannot be reached they stay with a note. It is emptied when the session ends, never holds unsent or failed messages, and never holds private chats. Not cached: attachments' files and avatars, which expo-image caches on its own, and read state.

**Parity polish (client#280, wave 4).** *Quick switcher:* the magnifier in the column header opens `QuickSwitcher` (`src/switcher`), a tall `BottomSheet` with a search field over every channel, conversation, server and a few screens (Friends, New message, Notifications, Discover, User settings). It ranks with core `quickSwitcher` (prefix `@` people, `#` text, `!` voice, `*` servers and `*server channel`; with nothing typed, chats with mentions come first, then unread ones, then recently visited ones) and builds its channel rows with core `channelSwitcherItem`, which desktop's palette now uses too. Return opens the first result. *Slash commands and components:* typing `/` in a standard chat where you have Use Application Commands lists the matching commands (`useSlashCommands` loads them through core `InteractionService`, now `runtime.interactions`); choosing one opens `CommandSheet` with a control per option (choices as chips, booleans as a switch, numbers and text with core validation, people, roles, channels and mentionables from a list inside the same sheet through core `entityChoices`), then Run sends the interaction and an "app is thinking" row waits at the newest end until the bot answers. Buttons, string selects (single, or multiple with Apply within the min and max values) and user, role, mentionable and channel selects that bots attach to messages render under the message (`MessageComponents`; link buttons open the in-app browser for http and https only), and a form a bot opens (`INTERACTION_MODAL_CREATE`) appears as `InteractionModal` at the root. File options are not supported yet. Stickers are not built: desktop has only the Animate stickers setting and no sticker sending or display. *Tablet layout:* `ios.supportsTablet` is on, and when the shorter side of the window is 600 pt or more (`src/shell/layoutModel`; an iPhone in landscape stays a phone) `WideShell` keeps the rail and a 288 pt channel column on the left and shows every stack screen to their right: a chat, the member list, pins, settings. Channels and conversations replace the chat in the pane (`openChat`) instead of piling up, a server in the rail opens the channel you were last in, and with nothing open the pane asks you to pick one. The app stays in portrait (`orientation` is unchanged) and `requireFullScreen` is set, which Apple requires of an iPad app that does not rotate or take part in Split View. *User panel:* the avatar carries the presence dot (the status the gateway reports, so automatic Idle shows; hollow while Invisible); the name opens `StatusSheet` with the four statuses (the chosen one ticked), the custom status editor (text and when it clears, also on the Profile page through `CustomStatusForm`), Edit profile and Settings, and the gear still opens settings. *Categories:* a collapsed category keeps what has activity listed, as desktop does (core `visibleChannelIds`): the open channel, mentions, unread text channels and voice channels with people in them. *Theme and accent:* they are read once when the app starts (styles are built at load), so the Appearance page says on the Theme and Accent rows that a change takes effect after a restart, and says so again after you change one. *Not built, needs an owner decision:* polls and voice messages are new on both clients (see `docs/handbook/13-mobile-client.md`).

- Expo SDK 58, React Native 0.88, React 19.3, TypeScript strict. All versions are pinned; check them with `npx expo install --check`.
- `app.config.ts` reads the display name, URL scheme (`voics://`) and bundle id/package from `../desktop/brand.json` (`displayName`, `protocolScheme`, `appId`). The icon is `../desktop/build/icon.png`. The bundle id and Android package are `nl.voics.app`.
- The workspace uses pnpm with `node-linker=hoisted` (root `.npmrc`), which Expo supports; Metro picks up the monorepo automatically. Desktop and mobile pin the same React version so there is one copy.

## Voice and calls (development build only)

Joining voice needs a development or preview build: @livekit/react-native-webrtc (WebRTC, with its frame cryptor) and react-native-incall-manager (speaker or earpiece) are native, and `src/voice/nativeVoice.ts` loads them only when `isNativeBuild` is true, so Expo Go still starts and shows the "not in this test version" notices. What works in principle (written against the core protocol tests and fakes; not yet run on a device):

- Join and leave a voice channel (tap it, then Join voice), mute, deafen, who is here, a green ring on whoever speaks, and a bar above the user panel while connected (mute, leave, tap to return). Speaker or earpiece switch on the call screen.
- DM calls: the voice button in a DM opens the call screen and joins (the server rings the others). An incoming call shows Accept and Decline over any screen while the app is open (`CALL_DECLINE` for decline). Ringing while the app is closed needs CallKit and PushKit, which come later.
- End-to-end encrypted calls (Ephemeral and P2P DMs, accounts with `e2ee_calls_default`, and any call where someone has it on) work like on desktop: the DAVE session runs on the Rust engine (`VoicsCrypto`), frames are protected by the native frame cryptor (`mobileFrameCryptor.ts`), the call header shows "end-to-end encrypted" once keys are active, and the Privacy page has the "Encrypt all my calls" switch. Nothing is sent or played in clear: the cryptor is attached and confirmed enabled before the answer is applied, a track reaches a sender only after that, remote tracks stay muted until their receiver is protected, and a call that announces another protocol version than 2, or H.264 video, or a phone without the crypto module is refused with a clear message. Needs a new development build (the WebRTC package changed to `@livekit/react-native-webrtc` 150.1.0). Not run on a device yet.
- Not included: video (the video button says it comes later), screen share, CallKit and PushKit.

How it is built: `@discordy/core` holds the voice session (`application/voice/voiceSession.ts`), the call controller (`voiceCallController.ts`), the media ports (`ports/media.ts`, `ports/voice.ts`) and `TurnCredentials`; the desktop extends the controller with camera, screen share and devices. Mobile supplies `createPeerConnection`, the microphone (`mobileMic`), the mixer (`mobileMixer`) and the audio route. The node never sends SDP, so the session builds the answer itself from the local offer; libwebrtc on iOS must produce an offer the parser accepts (to be checked on a device).

**Ephemeral and peer-to-peer chats (client#275, native build only).** In a development or preview build that contains the `VoicsCrypto` module, Ephemeral and P2P channels and DMs open as normal chats: they read from the encrypted store on the phone (`MessageSender.loadHistory`, never the server, never the plain message cache), send text through core `PrivateMessaging` (a failed send stays as a failed message with Retry), and show the same indicators as desktop: the delivery-mode badge under the header (`ModeBadge`: Standard, Ephemeral E2EE, Peer-to-peer), and above the composer the honest link state (`PeerStatusBar`: connecting, direct link open and verified, peer offline, identity unverified with sending blocked, encryption unavailable) with the safety number sheet. Expo Go has neither the crypto module nor react-native-webrtc, so there the runtime has no `privacy` engine and the "not in this test version" notices stay. Not on mobile yet: attachments in private chats (the file cipher uses WebCrypto, which Hermes lacks; the attach button is hidden there), editing, deleting, pinning and forwarding private messages (as desktop), E2EE calls. How it is built: `src/privacy/cryptoBridge.ts` adapts the Expo module `modules/voics-crypto` (Swift over the Rust core through uniffi; the store key lives in the iOS Keychain and never reaches JavaScript), `reactNativePeerConnection.ts` is the typed seam from react-native-webrtc to `PeerConnectionLike`, `nativePrivacy.ts` is the only place that loads either (lazily, in a native build only). The XCFramework is built by the manual `crypto-ios` GitHub Actions workflow on a macOS runner and fetched into the module by `scripts/fetch-crypto-framework.mjs`, which runs as the EAS hook `eas-build-pre-install` (it needs the EAS secret `VOICS_CRYPTO_GITHUB_TOKEN`) or by hand before `expo run:ios`. Core also gained a pure UTF-8 codec and SHA-256 fallback because Hermes guarantees neither TextDecoder nor `crypto.subtle`. Not yet run on a device: see the PR description.

**Push notifications (messages#56, api#93, native build only).** `expo-notifications` (the version `npx expo install` picks, ~58.1.8) is loaded only by `src/notifications/push/nativePush.ts`, lazily, in an iOS build where `isNativeBuild` is true; in Expo Go (and on Android until FCM exists) `loadNativePush()` is null and every push call does nothing, so the Notifications page says "Not available in Expo Go" and the app starts as before. `PushController` (everything outside it is injected, so it is unit-tested) listens from launch, so a tap that opened the app is kept until sign-in, then: with permission it registers the APNs device token through `POST /users/@me/devices/push` on every start (`environment`: `sandbox` for a development build, `production` for preview and store builds, from `extra.pushEnvironment` in `app.config.ts`; `previews` and `only_mentions` from the Notifications page), and registers again when iOS rotates the token or a preference changes. The permission is never asked at launch: the first time a chat is open the app explains what it is for ("Turn on notifications?") and only then shows the iOS prompt; "Not now" or a refusal is final, and the Notifications page offers Turn on or Open Settings. Logout removes the token first (`SessionManager` runs `beforeLogout`, then the server logout also drops it). Tapping a notification opens its chat and scrolls to the message (`openMessage`). While the app is open the system banner is suppressed when the gateway is live (the in-app banner covers it) or the chat is on screen, and shown only when the gateway is down, so a message is never shown twice or lost. The icon badge follows the unread mentions of the inbox while the app runs and is cleared at sign-out; the notifier does not send a badge count yet. The `expo-notifications` config plugin adds the `aps-environment` entitlement (`development` unless `EAS_BUILD_PROFILE` is `preview` or `production`). Push needs the Apple key in OpenBao (docs `runbooks/push-notifications.md`), a build signed with the Push Notifications capability, and a real iPhone: nothing here has been delivered to a device.

What each device-only risk needs: see the PR description of client#275 (microphone and audio session, `media-source` level stats, simulated SDP, react-native-webrtc under the new architecture interop layer).

## Motion and design (client#305)

Native libraries (a development build is needed for a new build; Expo Go bundles all four at these versions): `react-native-reanimated` 4.7.1, `react-native-worklets` 0.13.0, `react-native-gesture-handler` 3.3.0 and `react-native-keyboard-controller` 1.22.7. `app/_layout.tsx` wraps the app in `GestureHandlerRootView` and `KeyboardProvider`; the babel preset adds the worklets plugin by itself.

- **Keyboard.** The chat list is a `KeyboardChatScrollView` (inverted, `keyboardLiftBehavior="always"`, interactive dismissal) inside a `KeyboardGestureArea`; the composer dock is a `KeyboardStickyView` floating over the list, whose measured height is the list's `extraContentPadding`. Everything follows the keyboard frame on the UI thread, the list stays pinned to the newest message, dragging the list down closes the keyboard, and the dock drops its home-indicator padding by the sticky view's `opened` offset. There is no `KeyboardAvoidingView` any more; the sign-in form uses `KeyboardAwareScrollView`.
- **Gestures.** Sheets (`BottomSheet`), swipe to reply (`SwipeToReply`) and the member-list swipe (`MembersEdgeSwipe`, a 16 pt strip on the right edge of a server chat; drag 60 pt left or flick) use gesture-handler pans and reanimated shared values, with `swipeModel`, `sheetMotion` and `edgeSwipeModel` as the pure worklet rules the tests cover. The stack's back swipe works from anywhere on the screen (`fullScreenGestureEnabled`). Reduce Motion (app or iPhone) turns every movement into an instant change.
- **Scales and primitives** (`src/theme.ts`, `src/ui/`): `type` (desktop's 11 to 30 ladder), `space` (4 to 64), `radius` (6, 10, 14, 20), `HIT` (44), `CHROME_FONT_CAP` (1.3: text in fixed-height rows and chips stops growing there, message text grows freely). `Txt` (variant, tone, weight, `chrome`, `caps`), `PressableScale` (0.97 scale, 150 ms), `Button` (44 pt, `size="large"` 48 pt), `Input` and `Field` (accent border on focus), `ListRow` (52 pt), `SectionHeader`, `EmptyState` (icon tile, headline, sentence, one action) and the `Skeleton`, `MessageSkeletons` and `RowSkeletons` loaders that replace spinners and "Loading..." lines. New screens use these instead of their own sizes.
- **Jest.** Gesture-handler is mocked as chainable no-ops in `tests/setup.ts` and reanimated runs through its Jest resolver (`jest.config.js`), so gestures are tested through their pure models, not by simulated touches.

| `pnpm --filter @discordy/mobile lint` | ESLint (config shared via `eslint.base.mjs`) |
| `pnpm --filter @discordy/mobile test` | Jest (jest-expo) and React Native Testing Library |

The root `pnpm lint`, `pnpm typecheck` and `pnpm test:unit` run mobile too, so CI (the node workflow) checks it.

## Run it on a phone (no Mac needed)

1. **Expo Go (fastest).** Install Expo Go from the App Store or Google Play. Put the phone and PC on the same Wi-Fi, run `pnpm dev:mobile`, and scan the QR code (iPhone: Camera app; Android: Expo Go). If the phone cannot reach the PC (firewall, guest Wi-Fi), run `pnpm --filter @discordy/mobile start -- --tunnel`. Everything uses Expo Go compatible modules (including `expo-clipboard` and `expo-image-picker`, added for invite copying and the server icon).
2. **Development build.** Needed for voice (@livekit/react-native-webrtc is native; Expo Go does not have it). `eas.json` has two profiles, `development` (dev client, internal distribution) and `preview` (internal distribution, auto-increment); both are for a pnpm monorepo and run from `apps/mobile`. Build in the cloud with EAS (`npx eas-cli build --profile development --platform ios`); an iPhone build needs an Apple Developer account and the iPhone registered (owner steps, docs#10). Android is untested: `npx eas-cli build --profile development --platform android`. Then start with `pnpm --filter @discordy/mobile start:dev-client`.
3. **Simulators.** The iOS simulator needs macOS. On Windows use a real iPhone, or the Android emulator from Android Studio (press `a` in the dev server).

Full walkthrough: docs repo `runbooks/run-the-mobile-app.md`.

## Layout

| Path | Purpose |
|---|---|
| `app/` | expo-router screens: `index` (the main screen: rail, column, user panel), `servers/[guildId]` and `dms` (the same screen with that view selected), `servers/[guildId]/[channelId]` and `dms/[channelId]` (chats), `dms/new`, `friends`, `pins/[channelId]`, `threads/[channelId]`, `search/[channelId]`, `settings` (list and `[page]`), `notifications`, `sign-in` |
| `src/shell/` | the main screen: server rail, channel and DM columns, channel rows, the server menu, user panel and its status sheet; `railModel` holds the unread and mention rules; `Sidebar`, `WideShell` and `layoutModel` hold the tablet layout |
| `src/native/` | `isNativeBuild`: false in Expo Go, so native modules are never loaded there |
| `src/privacy/`, `modules/voics-crypto/` | Ephemeral and P2P on mobile: the CryptoBridge adapter, the react-native-webrtc peer connection, the mode badge, peer status bar and safety number sheet; and the Expo module (Swift, Keychain) over the Rust XCFramework |
| `src/voice/`, `src/members/`, `src/invites/`, `src/serverSettings/` | the voice channel screen and occupant list, the member list, invite creation, and the server settings pages (each page with its permission model) |
| `src/sheets/` | `BottomSheet`, the one bottom sheet for every sheet in the app (the message menu, profile, select-text and, through `src/ui/Sheet`, the server menu and admin sheets): a separate 45% backdrop fade, only the sheet slides, drag the handle (a gesture-handler pan on the UI thread) or tap outside to dismiss, keyboard dismissed first, lifted with the keyboard frame, safe area and Reduce Motion respected |
| `src/pins/`, `src/threads/`, `src/search/` | the Pins panel, thread creation and list, and search (target, runner, tabs, results) |
| `src/notifications/`, `src/friends/`, `src/dms/` | the mentions inbox, in-app banner and push (`push/`), the Friends page, and the DM list model, menu, commands and New message picker |
| `src/navigation/` | stack options, `openChat` and `openGuild` (replace the chat beside the list on a tablet, push on a phone) and `openMessage` (open a chat at a message) |
| `src/switcher/`, `src/commands/` | the quick switcher (items, sheet), slash command search and sheet, the "thinking" rows, the root modal for forms a bot opens and the people, role and channel picker |
| `src/emoji/` | the emoji picker sheet (search, recently used, the server's custom emoji, unicode categories) and its model |
| `src/haptics.ts` | light, selection, success and error haptics through expo-haptics, silent while Reduce Motion is on |
| `src/messages/components/` | buttons and select menus bots attach to messages |
| `src/messages/attachments/` | attachment grid, media viewer, audio and file rows, and the grid and size model |
| `src/messages/markdown/` | the React Native renderer for `domain/markdown` (bold, italic, strike, underline, code, code blocks, quotes, lists, headings, tables, spoilers, mentions, custom emoji, timestamps, links through expo-web-browser with the desktop's trusted-host confirmation) |
| `src/ui/` | small shared controls: bottom sheet wrapper, buttons, text field, chips, list row, `attempt` for failures |
| `src/adapters/` | Keychain session vault, key-value storage, WebSocket factory (ports from `@discordy/core`) |
| `src/runtime/` | composition root (`createRuntime`), foreground resume policy, the app runtime |
| `src/signIn/`, `src/servers/`, `src/messages/` | sign-in screen and error handling, server and channel models, the channel screen with its message service and permission model |
| `src/` | brand (installed first), theme |
| `tests/` | Jest tests with fakes for the keychain, storage and sockets |
