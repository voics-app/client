# Desktop renderer performance

The renderer loads settings (including server administration), the emoji picker and slash-command panel on demand. A failed import is retried after 250, 500 and 1000 ms. The error offers another attempt, close, and an explicit app reload; reload can discard unsaved work. A browser may cache a failed module fetch for the life of a document, so a reload can be necessary even after connectivity returns.

Build with `pnpm --filter @discordy/desktop exec electron-vite build`, then run `node apps/desktop/scripts/check-renderer-budget.mjs`. The Vite manifest defines the entry and its transitive static imports; CI prints each JavaScript asset and fails if their combined uncompressed size exceeds 2,800,000 bytes. Dynamic chunks, CSS, workers and compressed size are excluded. Keep the threshold under review when dependencies or the app's initial feature set change; do not increase it without recording a new baseline and reason.

For cold-start acceptance, use a fresh isolated user-data directory on the agreed reference VM, with the same build type, hardware load, network and account state for both versions. Measure process launch to a visible signed-out auth screen repeatedly, record each sample and the median, and distinguish this from a warm start or synthetic backend test. Never use a production account for the isolated test.

The service catalog names a reference Windows laptop for the cold-start SLO but does not identify it or define a fresh profile. For client #24, the existing self-hosted Linux CI runner and the Playwright 1.56.1 Ubuntu container are an additional reproducible reference, not evidence that the Windows SLO passed. Each sample launches a new process with a new user-data directory; operating-system page caches are not flushed. The fake-backend test does not measure production network latency.
